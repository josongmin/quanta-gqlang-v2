## Corrections and constraints for the RFC/action list

1. **Define the finite, monotone subset before promising recursion.** Grounding alone does not bound derivation with arithmetic/functors. Soufflé itself rejects an auto-increment functor in a recursive rule ([SemanticChecker.cpp:513–518](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/transform/SemanticChecker.cpp#L513-L518)), and its magic-set implementation warns that certain recursive bindings can create an infinite magic relation ([MagicSet.cpp:629–645](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/transform/MagicSet.cpp#L629-L645)). Proposed first subset: finite provider domains, constants, equality/comparisons, positive recursive predicates, and stratified `not` over admitted complete lower strata. Reject value-generating recursive functions, non-monotone recursion and unsupported aggregate cycles. This is a design recommendation, not a claim that Soufflé supports only this subset.
2. **Preserve clauses, not only relation dependencies.** Soufflé's translator consumes every literal and generates a clause version for every same-SCC positive occurrence. A04 requires the following executable shape: relation declaration, typed columns, rule head, ordered body atom occurrences, comparisons, negations, alternatives, and source/span IDs. Keep `OR` normalization bounded; reject expansion overflow with a typed diagnostic. The need for this shape follows from [Clause.h:38–76](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/Clause.h#L38-L76) and [UnitTranslator.cpp:403–410](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast2ram/seminaive/UnitTranslator.cpp#L403-L410).
3. **Specify semi-naive state and differential cases.** A07 requires `main_r`, `delta_r`, `new_r` for each relation in an SCC and one translated alternative for each positive recursive body atom. Assert the equality of complete least fixed point, not iteration counts. Include a rule with two recursive body atoms, mutual recursion, duplicate paths, empty base, zero-arity and cyclic graph cases. A consumer that evaluates only one selected recursive atom could miss results.
4. **A resource cap is a semantic outcome.** Soufflé's `.limitsize` path exits the fixpoint loop when a relation reaches a size limit ([UnitTranslator.cpp:717–748](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast2ram/seminaive/UnitTranslator.cpp#L717-L748)). QGLang/Semantica's RFC promises typed non-success on a bound. Keep that stronger contract: any tuple, work, memory or deadline cap reached before convergence returns `Incomplete`/resource failure and cannot issue a completed zero-result or absence result. Test below/at the closure cardinality and with sufficient additional budget to certify no-new-tuples convergence; cardinality equality alone cannot certify completion.
5. **Runtime type storage can be compact while public identity stays nominal.** Soufflé type-checks relation attributes ([TypeChecker.cpp:345–380](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/transform/TypeChecker.cpp#L345-L380)), then builds RAM relations from arity and type qualifiers ([UnitTranslator.cpp:839–855](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast2ram/seminaive/UnitTranslator.cpp#L839-L855)); interpreter values use `RamDomain` ([Engine.h:67–90](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/interpreter/Engine.h#L67-L90)). This is no justification to expose arbitrary string/int cell equality across Semantica providers. Preserve a typed public schema and checked canonical entity ID conversion even if physical rows use compact domains.
6. **Demand specialization is a later, guarded optimization.** Soufflé makes magic-set rewriting conditional ([MagicSet.cpp:275–281](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/transform/MagicSet.cpp#L275-L281)); it excludes/handles cases involving negation, floating constraints, functional dependencies, execution plans and stateful counters ([MagicSet.cpp:123–180](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast/transform/MagicSet.cpp#L123-L180)). Recursive A12 transformations require A07 correctness; unrelated join optimization does not. A bound source query is not by itself a safe reason to prune `not`, aggregate or flow input.
7. **Provenance is separately costed and validated.** A11 uses lazy evidence. Define an observable policy for duplicate derivations, stable finding key independent of witness choice, witness edge membership in the admitted source, depth/branch caps and memory charge. Soufflé's explicit provenance strategy demonstrates that proof semantics influence representation, not just response formatting ([provenance/UnitTranslator.cpp:55–91](https://github.com/souffle-lang/souffle/blob/f53dab8bf4bbf2395a26d2771f6b75395825cc46/src/ast2ram/provenance/UnitTranslator.cpp#L55-L91)).
8. **Index choice belongs with physical access, not the frontend contract.** A01-F's supported bindings and A06's operator review are required inputs; A08-I's Quanta Index adapter cannot replace RAM-style equality indexes for `Method × CallEdge` or recursive deltas. This follows from the separate Soufflé index analysis and interpreter relation creation above. A benchmark should report candidate scans and index bytes, not just output rows and query latency.

## Reuse decision

Adopt the **semantic pattern**: typed/range-checked rules, SCC validation, stratified negative/aggregate dependencies, explicit per-relation delta/new/main sets, access-pattern-based indexes, and separate bounded provenance. Do not import the C++ Soufflé runtime for the initial public slice. It would require new C++ build/FFI and ownership of Semantica source authority, provider completeness, request cancellation, typed outcomes and source-sealed entity keys at that boundary. Existing Semantica recursive and physical executors are the first compatibility targets. Reconsider an embedded engine only after A06/A07 differential tests show an irreducible gap and a measured implementation-cost advantage.

## Required proof before claiming this design applied

- Static producer check: every authored rule head/body occurrence survives QGLang lowering into V4 with stable IDs and deterministic digest; malformed or excessive expansion fails.
- Independent evaluator: execute a finite, typed set oracle for base, two-atom recursion, mutual recursion, duplicate paths, negation on complete/partial facts, and invalid recursion. Compare tuples **and** final status.
- Installed Semantica path: public source → admission → actual provider facts → recursive physical execution → typed output. Check wrong generation, incomplete provider, cancellation and each cap. Same output under reversed provider row order.
- Profile: record SCC iteration delta sizes, join candidates, retained index bytes, peak RSS and work charge on a fanout corpus. This is needed to justify semi-naive and any demand rewrite; source inspection alone establishes no speedup.
