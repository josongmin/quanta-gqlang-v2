## Why this target

Calcite supplies an inspectable memo/trait optimizer, but is Java. egg is an actual Rust library candidate for equality saturation. Its role would be optimizing a checked logical expression, not compiling QGLang, admitting source facts, executing recursion, or solving data flow. Syntax rewrites and e-graph saturation do not prove language laws.

## Reachable implementation

## Existing Semantica boundary

The local query-owner [cost facade](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-runtime-query-owner-surface/src/planner/cost.rs) re-exports `quanta-planner-contract`. `quanta-planner` already has enumeration, rewrite, cost and selection owners. The inspected [gqlang physical lowering](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-runtime-execution/src/gqlang/physical_plan_v1/lowering.rs) validates topology and maps logical nodes to physical operators at lines 1264–1354. This is not evidence that all planner paths lack optimization, nor that this mapping implements relational join reordering.

Before adding egg, map which existing planner owner selects provider/capability alternatives, which lowers typed relations, and where a legal relational alternative could be selected. Keep one owner for admission and physical selection.

## Required gates and final disposition

1. Retain an admitted deterministic baseline before optimizing. Define schema, scope, source, effects, result multiplicity and required physical traits for every alternative.
2. Independently check each rewrite on duplicate-bearing inputs, `Option<T>`, correlated bindings, residual filtering, outer/anti joins where supported and order/limit. Reject unsupported variants. Moving limit before a filter that drops the first candidate is a mandatory counterexample.
3. Stats may influence cost and the existing estimated-budget candidate filter, not semantic capability, provider exactness or completeness. Unknown/stale estimates must not create unsupported operators or silently remove result rows. A conservative budget refusal stays typed.
4. A bounded optimizer may return the best valid candidate found without saturation. It must report the stop reason and cannot claim optimality. If no valid candidate exists, reject; never invent one. Cancellation and mandatory request/resource failure remain terminal.
5. Measure end-to-end planning time, peak retained memory, execution work and result equivalence against the existing owner before choosing a dependency. Bound one rule's match expansion and extractor/rebuild work, not only iteration count.

**Decision:** use guarded rewrite/cost/explanation patterns in A06/A11/A12. Defer egg production adoption until the typed relational baseline and workload exist. Neither an e-graph nor a whole-engine replacement is required for the first installed two-fact query.
