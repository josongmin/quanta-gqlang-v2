# Joern source audit for flow and witness semantics

> 고정 SHA의 소스 감사 기록이다. 로컬 구현·계획 언급은 감사 시점 관찰이며, 현행 판단은 [근거 인덱스](../2026-10-04-reference-source-review.md)와 [RFC](../../rfcs/2026-10-04-code-query-dsl-and-substrate.md)를 따른다.

- Upstream: `https://github.com/joernio/joern`, cloned at `bf4f3434c28dae885f8bdf2e5540e311f77836e4` (2026-10-04 review).
- Scope: CPG data-flow overlay, traversal entry points, backward query engine, external semantics and one Java SQL-injection scanner. Source inspection only; build, execution and benchmark not run.

## Reachable implementation chain

1. [`OssDataFlow`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/layers/dataflows/OssDataFlow.scala#L8-L25) runs a reaching-definitions pass with a default 4,000-definition threshold. [`ReachingDefPass`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/passes/reachingdef/ReachingDefPass.scala#L21-L50) skips methods that exceed it, leaving dependencies uncalculated. This is a concrete case where a completed scan can have absent edges because of a local analysis bound.
2. Traversal [`reachableBy`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/language/ExtendedCfgNode.scala#L31-L38) returns reached sources. [`reachableByFlows`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/language/ExtendedCfgNode.scala#L40-L63) returns path objects, filtering invisible steps and deduplicating. Both call the same [`Engine.backwards`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/language/ExtendedCfgNode.scala#L76-L97) on sinks sorted by ID. This demonstrates a useful endpoint/path API split, but path projection affects which internal steps the user sees.
3. The [engine](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/Engine.scala#L18-L54) schedules backwards tasks in a work-stealing pool, with task fingerprints and a result table. [`TaskSolver`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskSolver.scala#L71-L148) memoizes local paths; [`TaskCreator`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskCreator.scala#L33-L59) carries a call-site stack to avoid unrealizable interprocedural paths. A plain graph reachability BFS would lose this call/return semantics.
4. [DefaultSemantics](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/DefaultSemantics.scala#L9-L27) supplies modeled operator and common external-call mappings. [Semantics](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/semanticsloader/Semantics.scala#L8-L39) supports per-method lookup and composition. The engine uses the model during edge expansion and [distinguishes internal calls lacking semantics](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/Engine.scala#L243-L295). Model presence changes which edges and interprocedural expansions exist.
5. **Limits can silently change negatives in this implementation.** [`EngineConfig`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/Engine.scala#L300-L326) defaults to call depth 4 and argument/output expansions 1,000. [`TaskCreator`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskCreator.scala#L22-L30) filters over-depth tasks, [returns no callers](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskCreator.scala#L68-L79) when argument count exceeds the cap, and [drops output expansion](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskCreator.scala#L175-L182) above its cap. [`Engine`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/Engine.scala#L96-L109) logs worker failure and continues. The reviewed APIs return source/path iterators, with no typed completeness status at those sites. This is a design lesson, not a claim that Joern has no status elsewhere.
6. **Representative path is not shortest.** [`TaskSolver`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/TaskSolver.scala#L89-L116) keeps maximum length among duplicate local endpoint/context paths. Final [`Engine.deduplicateFinal`](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/dataflowengineoss/src/main/scala/io/joern/dataflowengineoss/queryengine/Engine.scala#L154-L179) groups by source/sink, selects maximum length, then picks an internal-ID ordering tie-break. The final `groupBy(...).toList` does not explicitly sort endpoint groups; the visible code therefore does not prove result-list order. The prior RFC's unqualified shortest+lexical witness policy is a local design choice requiring explicit solver proof, not a common reference property.
7. A Java [SQL-injection scanner](https://github.com/joernio/joern/blob/bf4f3434c28dae885f8bdf2e5540e311f77836e4/querydb/src/main/scala/io/joern/scanners/java/SQLInjection.scala#L10-L38) selects framework sources and sink parameters and calls `sink.reachableBy(source)`. Its source-level description itself says validation/sanitization is a condition, while this query body does not model a sanitizer predicate. Do not use this query as a precision baseline against CodeQL's SQL model without harmonizing policy.

## RFC impact

| RFC item | Source-based verdict | Required correction or gate |
| --- | --- | --- |
| A01/A05 fact quality and completeness | The overlay can skip individual methods at a threshold. | Each provider slice needs a policy-relative coverage record by method/fact family; `complete` must account for local skipped work, not only overall job termination. |
| A09 model semantics | Per-method mappings and call-context control are integral to result quality. | Model pack must state unknown external-call fallback, call/return matching and covered Java APIs. Test actual sanitizer and ambiguous dispatch cases. |
| A10 endpoint/path result | Endpoint and path APIs can share a solver while exposing different result representations. | Retain separate endpoint and path capabilities; validate emitted path against solver state, and surface cap/exception as typed non-success. |
| Prior RFC representative witness | Joern chooses maximum-length representatives in this version. | Use a versioned path-policy capability. Claim shortest/lexical only for an implemented, measured Semantica solver or verified adapter. |
| A14 comparison | Joern Java scanner's selected semantics differ from CodeQL's SQL query/model. | Compare at equivalent source/sink/sanitizer/unknown-call policy or report the divergence per case, never as a raw accuracy ranking. |

No performance, correctness, completeness or CodeQL-relative quality conclusion follows from this read-only source audit.
