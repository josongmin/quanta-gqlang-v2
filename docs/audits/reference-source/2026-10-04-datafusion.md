## Library adoption threshold

DataFusion is an executable reference for physical boundary design. Its current planner admits custom `TableSource` extension planning ([`ExtensionPlanner::plan_table_scan`](https://github.com/apache/datafusion/blob/9547b091bc99fbcd52c37d67f9ccee645cffc2ae/datafusion/session/src/planner.rs#L123-L129)). A direct integration would also require mapping QGLang nominal code-entity keys and explicit `Option<T>` semantics into Arrow rows, binding each provider to Semantica's issued source generation, preserving completeness/cancellation/status across its stream, and excluding recursive rules plus taint witnesses from relational rewrites. The source review does not establish those adapters or semantic equivalence.

The present choice is to keep Semantica's existing physical executor as the first A06 candidate. Reconsider DataFusion only after A00/A01 real fact slices and A06 reference-evaluator proof exist, using the same corpus, source pin, result/status laws, memory limit, and cold/warm workload. Adopt a full library only if a prototype measurably improves the named workload without losing those laws; do not interpret a working SQL join as a CodeQL-class analysis result.

## Source-derived contract requirements

1. A01 fact provider: specify predicate-specific pushdown exactness and residual-filter obligations, separate from relation completeness.
2. A06 physical bridge: make row streaming, cancellation on drop, pre-allocation memory reservation, and ordering/partition properties explicit acceptance gates.
3. A06 semantics: require a per-operator compatibility matrix, especially QGLang `Option<T>` versus nullable anti-join behavior.
4. A08 query completion: distinguish provider fetch hints, per-partition local limit and final globally ordered limit; prohibit unsafe early cap before join/filter/negation.
5. A11 explain: mark optimizer estimates as estimates and show actual rows, memory/spill, ordering/partition and cancellation status without treating estimates as authority.

These source-derived requirements are incorporated in the RFC; implementation remains subject to its action gates. The source audit found no basis to replace Semantica's physical executor or to add DataFusion as a dependency before the two-fact public query is proven.
