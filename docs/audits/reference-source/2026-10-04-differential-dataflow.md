## Decision and correction to the plan

**Required now:** Keep A07's finite snapshot reference evaluator and semi-naive `main/delta/new` implementation; prove installed two-fact joins before broadening the runtime. Differential Dataflow is not required for those gates. Its signed-weight and frontier model is the strongest reviewed reference for **A13 incremental semantics**, but A13 is a later, separately measured milestone. Adding this crate now would force Timely scheduling, trace lifetime, source-generation to logical-time mapping, query-plan lifetime and cancellation ownership into the first vertical slice without a measured incremental workload.

**A13 contract to add to the RFC/action list:** define a publication epoch with a monotone input frontier per fact owner; represent insertions and deletions with owner-scoped stable tuple identity and checked multiplicity; deduplicate/reject replayed or out-of-order epoch batches before applying weights; seal all inputs before claiming a result at that epoch; retain arrangements, source leases and evidence until active queries/cursors finish; advance compaction only past the oldest required epoch; publish `Complete` only after all required output frontiers advance and the provider/solver completeness checks pass. Abort/restart on source/model/schema identity change when a lawful delta cannot be produced. This can be implemented with or without Differential Dataflow. The inspected `InputSession::update` appends each call as a new weighted update; it supplies no source publication deduplication.

**Adoption gate, if A13 workload warrants it:** compare an instrumented prototype against fresh snapshot recomputation and the existing Semantica engine on the same sealed fact changes. Require exact rows, multiplicities, status, witness source identity and stable ordering at every checkpoint, including delete/rollback and concurrent held cursors. Measure cold/warm latency, peak RSS, retained trace bytes, compaction lag and cancellation latency. Reject adoption if a hard request memory/work bound or typed incomplete result cannot be enforced without a larger runtime rewrite than the measured gain justifies.

## Independent acceptance oracles

1. A path with two alternative routes: deleting one route leaves the endpoint; deleting the last route retracts it. Compare every published epoch with a fresh finite closure oracle. This catches naive deletion propagation through recursion.
2. Duplicate fact rows and duplicate join keys: set output stays one; bag multiplicity equals the independent product-and-sum oracle. Retraction never leaves a negative completed row.
3. A negated predicate toggles across epochs, including a provider coverage gap. Absence is publishable only after the relevant lower stratum and provider coverage complete.
4. A model or source schema changes without a valid tuple delta: the old arrangement is invalidated, and a new query cannot reuse its evidence.
5. A reader holds an old epoch while newer epochs arrive: compaction preserves the old cursor/evidence; after lease release the trace may compact. A canceled reader cannot later publish `Complete`.
6. Bound exhaustion, missing flush, or a held capability: no apparent quiet loop may become a completed scan until all required frontiers and custody checks close.
7. Replay, reorder or restart a provider's delta batch, and retract one of two owners' identical tuple values: each publication is applied once, the remaining contribution survives, and fresh snapshot results still agree.

**Verification scope:** `git rev-parse`, crate metadata and a clean `git status` were observed; the cited implementation paths were inspected. No Cargo build, dynamic insertion/deletion test, performance comparison, Semantica adapter or local `just ci` was run for this audit. The oracles above are required future gates, not passed tests.
