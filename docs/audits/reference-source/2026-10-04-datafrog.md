## Source mechanisms

| Mechanism | Pinned source | QGLang/Semantica implication |
| --- | --- | --- |
| Relations sort and deduplicate typed `Ord` tuples | [relation.rs:9–17](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/relation.rs#L9-L17), [from_vec:77–81](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/relation.rs#L77-L81) | Fits finite set-valued rules. Nominal provider/source identity must still be supplied by Semantica's tuple type; the library cannot validate it. Bag queries remain a different contract. |
| Variable lifecycle is pending → recent → stable; duplicate tuples are excluded from the next delta | [variable.rs:339–394](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/variable.rs#L339-L394) | A07 can implement compact typed delta evaluation without importing a full C++ engine. Keep per-relation delta state and source-bound completion outside this library. |
| Binary recursive joins cover recent×stable, stable×recent and recent×recent | [join.rs:44–62](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/join.rs#L44-L62) | Nonlinear recursion must account for both recursive inputs. A single selected new-row side is not sufficient in a two-recursive-atom rule. |
| Anti-join's right input is a fixed `Relation`, not a varying recursive variable | [variable.rs:165–200](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/variable.rs#L165-L200) | Aligns with a completed lower stratum. The caller must establish stratum ordering and complete, sound absence authority; fixed storage alone is not completeness proof. |
| Iteration is driven by the caller; indistinct variables can re-advertise duplicates indefinitely | [iteration.rs:22–53](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/iteration.rs#L22-L53) | Only admitted finite monotone rules with distinct tuple state can justify convergence. A host-controlled loop provides cancellation checkpoints, but that does not bound each join allocation. |
| Join materializes into an internal `Vec`; merge allocates combined capacity; `complete` asserts convergence | [join.rs:12–23](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/join.rs#L12-L23), [merge.rs:27–30](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/merge.rs#L27-L30), [variable.rs:323–334](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/variable.rs#L323-L334) | Current API has no request-scoped fallible reservation/cancellation in those operations. Checking tuple count after `from_join` cannot enforce the RFC's pre-allocation bound. Early budget exit must not call `complete` as though fixed point succeeded. |
| Leapjoin chooses a smallest candidate proposer but collects intermediate values/results internally | [treefrog.rs:5–44](https://github.com/rust-lang/datafrog/blob/edd7cfc0f5ad3b93ce5bbe6a17848db9376b13c0/src/treefrog.rs#L5-L44) | A useful access-pattern reference for n-ary joins, with the same budget integration gap. ## Executed probe

Probe source and output are outside the product checkout:

- `/Users/songmin/Documents/code-new/.reference-audits/2026-10-04-code-query/probes/datafrog/probe.rs`
- `/Users/songmin/Documents/code-new/.reference-audits/2026-10-04-code-query/probes/datafrog/result.json`

The library was compiled directly with `rustc --crate-type lib src/lib.rs`; a separate `rustc --test` binary linked that exact library. **Three tests passed**:

1. All 512 directed graphs over three nodes, with duplicate input edges, compared both linear and nonlinear recursive closures against an independent Floyd–Warshall oracle: 1,024 tuple-result comparisons.
2. A fixed lower-stratum anti-join over all eight subsets of three keys matched independently enumerated expected tuples.
3. An indistinct self-cycle continued reporting changes for 16 controlled iterations, confirming that termination depends on the selected tuple/rule policy.

This checks the narrow finite algorithms used in the probe. It does not establish general language support, source authority, memory/work bound, cancellation latency, incremental deletion or performance.

## Adoption decision

Keep Datafrog as an A07 comparison/prototype candidate and an additional algorithm reference. Do not add it as a production dependency solely because the finite probe passes. A production decision requires typed dynamic RuleProgram lowering, bounded/fallible join and merge allocation, within-operation cancellation, source/capability/status integration and measured total adaptation cost. Retrofitting those constraints may cost more than repairing Semantica's existing recursive operator owner; the current audit does not measure that cost.
