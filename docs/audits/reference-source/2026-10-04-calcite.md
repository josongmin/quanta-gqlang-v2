## Reachable implementation path

1. `Programs.standard` sequences subquery handling, decorrelation, field trimming, physical optimization and a later physical tweak pass; the planner sets a root, converts required output traits and calls `findBestExp`. This is an explicit *logical rewrite → physical choice* boundary, not just a tree of operators. [Programs.java:317-360](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/tools/Programs.java#L317-L360)
2. `VolcanoPlanner.setRoot` registers the expression in equivalence subsets and requires root converters; `findBestExp` drives rules, then builds the cheapest implementable tree. The memo tracks `RelSet` logical equivalence and `RelSubset` required/delivered traits plus best cost. Cost changes propagate to parents and clear cached metadata. [VolcanoPlanner.java:275-283](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/volcano/VolcanoPlanner.java#L275-L283), [VolcanoPlanner.java:515-547](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/volcano/VolcanoPlanner.java#L515-L547), [RelSubset.java:84-130](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/volcano/RelSubset.java#L84-L130), [VolcanoPlanner.java:955-1018](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/volcano/VolcanoPlanner.java#L955-L1018).
3. `HepPlanner` executes ordered rewrite programs with match order and match limit. `findBestExp` applies the program and builds the final tree. This is useful for bounded, proven normalization, but a match limit can stop before a rewrite fixed point; it is not an execution completeness proof. [HepProgram.java:73-79](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/hep/HepProgram.java#L73-L79), [HepPlanner.java:284-292](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/hep/HepPlanner.java#L284-L292), [HepPlanner.java:508-565](https://github.com/apache/calcite/blob/fe1c46d2beff6e1edcc050ffbb03df1724adbaf3/core/src/main/java/org/apache/calcite/plan/hep/HepPlanner.java#L508-L565).
4. Row-count/selectivity come from table handlers or fallback estimates. ## Local fit and correction to the plan

- Semantica **does have** `quanta-planner` costed enumeration and selection. The observed enumerator emits one sequential plan and optionally one parallel dependency plan, then the selector gates by rail/capability/estimated budget. It is a query/dependency execution choice, not Calcite-style alternative relational join orders or physical access paths. Estimated budget admission does not replace execution-time work accounting and memory reservation. No join/access alternative enumeration is visible in this bridge. Existing `universal_executor_v1` join/aggregate/sort/limit operators remain reusable execution assets, subject to semantic and resource gates. [lowering.rs:1264-1354](/Users/songmin/Documents/code-new/semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-runtime-execution/src/gqlang/physical_plan_v1/lowering.rs), [physical_lowering_v1.rs:464-481](/Users/songmin/Documents/code-new/semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-runtime-execution/src/gqlang/physical_lowering_v1.rs).
- A Calcite dependency would cross Java/Rust and SQL/entity/flow semantic boundaries and would still need Semantica's source closure, nominal entity keys, provider exactness and typed `Incomplete`. **Do not adopt Calcite or build a general memo now.** First implement the A06 two-fact join. A12 may add a small, deterministic choice among proven equivalent access/join implementations after real row counts and work measurements exist. This is a sequencing judgment, not a measured performance verdict.
- For any later optimizer, equivalence is conditional on set/bag, Option versus SQL null, correlation scope, negation authority, deterministic expression evaluation, and complete provider candidate sets. Treat ordering/partitioning as required physical properties, estimates as advisory, and budget/capability/source proofs as hard admission. A final ordered limit cannot be pushed below residual filters or a join without an equivalence proof.

## Acceptance tests to add before optimizer claims

1. Differentially compare each rewrite and chosen plan against the typed reference evaluator on duplicates, `Option`, correlated `EXISTS`, `NOT EXISTS`, anti/semi join, residual filters, row reorder and deterministic `order/offset/limit`. Include a counterexample for each forbidden pushdown; plan-shape snapshots alone are insufficient.
2. Vary provider statistics while holding facts/source generation fixed. With sufficient resource budgets, every admitted plan must produce the same completed typed rows and semantic status. Under restrictive budgets, estimates may alter plan choice or cause `NoPlanFitsBudget`, and different legal plans may exhaust actual resources; each path must retain typed failure, source custody and no fabricated completeness. Missing or stale stats must never grant provider completeness or exact predicate support.
3. If search is bounded by planner time/matches, either return a fully valid best-known plan with `optimization_truncated` explain metadata after independent admission, or reject `NoAdmissiblePlan`. Request cancellation, deadline, memory exhaustion and incomplete facts remain typed non-success; no fallback plan may erase them.
4. Measure two-fact and selected multi-fact workloads with recorded source/model/Index tuple, row counts, cardinality estimation error, planning time, execution time, peak memory and work. Add a rewrite or memo only when it improves a named workload without correctness or resource regression.

## Verdict

The transferable pattern is **semantic admission → validated logical plan → guarded alternatives → cost choice → physical execution with explicit traits**. Calcite's memo and heuristic join order solve a larger search problem than the current installed QGLang path. A06/A08 need an executable and correct bridge first; A12 should explicitly distinguish Semantica's existing query/dependency planner from missing per-operator relational alternatives.
