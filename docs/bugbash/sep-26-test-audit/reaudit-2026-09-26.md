# Sep 26 test audit 재검증

현재 처리 상태: 아래 감사 이후 RA-01~05와 선택 보강을 구현했다.
마지막의 **구현·검증 기록**이 현재 상태이며, 최초 감사 본문은 당시 근거로 유지한다.

감사 기준: `f56445776245d9f01480c502690d8f7e423365d3`, 시작 시 clean worktree.
기존 문서 11개를 3개 read-only worker와 통합자 1명이 현재 소스·테스트와 대조했다.
생산 코드나 테스트는 수정하지 않았고, 이 보고서만 추가했다.

확인한 범위에서 생산 동작 결함은 발견하지 않았다. 기존 수정은 유지되어 있다.
추가 작업은 아래 3개 P2 검증 공백을 우선하고, 2개 P3 oracle 개선은 작은 후속 작업으로 묶는 것이 적절하다.
여기서 P2/P3는 **테스트 개선 우선순위**이며 생산 장애 심각도가 아니다.
이번 감사에서 mutation은 실행하지 않았다. 아래 mutant 설명은 현재 assertion 구조에서 도출한 정적 분석이다.

## 우선 개선

### RA-01 / P2: 외부 callable의 non-default effects 보존

- 근거: `crates/quanta-gqlang-v2-modules/tests/v3_modules_v2_authority.rs:3867,3910`은 입력·출력 모두 `pure_scalar()`이다. 같은 파일의 모든 `SignatureInputV2`, `v3_document_predeclaration.rs:124,673`, sema의 해당 fixture도 기본 effects만 제공한다.
- 생산 경로: `modules/src/signature.rs:116,130,148`에서 입력 effects를 signature와 두 callable projection으로 전달한다. 공개 입력은 다섯 effects 축의 다른 값을 허용한다(`types/src/builtin.rs:33`, `types/src/check.rs:329,373`).
- 공백: 이 경로에서 effects를 항상 `pure_scalar()`로 대체해도 기존 기본값 oracle은 구별하지 못한다. Types의 non-default callable 테스트는 callable을 직접 생성하므로 Modules projection을 검증하지 않는다.
- 최소 변경: 기존 public projection 테스트에 non-default 다섯 축을 가진 입력을 추가하고 `signature.effects()`와 `projected.effects()` 전체 equality를 요구한다. document host-predicate resolution에도 같은 입력을 넣고 `proof.callable().effects()`를 요구한다.
- 종료 조건: 입력 보존과 두 projection을 각각 기본값으로 치환하는 **compiling** mutation이 해당 테스트에서 실패한다. 반환값에 기대값을 다시 계산하는 방식은 피한다.

### RA-02 / P2: EXPORT `Some(profile)` 의미 해석 경로

- 근거: `sema/src/document.rs:5264-5297`은 EXPORT profile을 별도로 charge하고 `NamespaceKindV2::Profile`로 resolve한다. 현재 sema fixture와 payload oracle은 `profile: None`만 사용한다(`sema/src/test_support.rs:4136,5092-5095`).
- 기존 커버리지: `surface/tests/v3_family_hellgate.rs:465`, `v3_format_hellgate.rs:722`는 parse/format, `hir/tests/v3_visit_traversal.rs:165`는 span traversal이다. `examples/export/sarif.qglang`도 존재하지만 closed-authority conformance의 선택된 네 예제에는 포함되지 않는다(`conformance/tests/self_validation.rs:328-343`). 이들은 해당 의미 해석의 성공을 증명하지 않는다.
- 최소 변경: authored Profile을 가진 EXPORT 성공 fixture에서 profile id/kind/origin/source-qualified use span을 확인한다. 별도로 absent profile과 wrong-kind profile을 exact diagnostic/location으로 거부해야 한다.
- 종료 조건: profile을 `None`으로 버리는 mutation, 다른 namespace kind로 resolve하는 mutation, use span을 전체 EXPORT span으로 바꾸는 mutation을 구별한다. 기존 `None` control은 유지한다.

### RA-03 / P2: Query composition binding의 schema/relation 누락 검출

- 근거: `pipeline/tests/v3_compiled_document_assembly.rs:2240-2285`, `every_projected_expression_reference_resolves_within_its_own_table`은 SAMPLE과 Query 전체에 단 하나의 `bindings_with_schema` counter를 사용한다.
- 공백: Query producer의 schema와 relation을 둘 다 누락하면 `schema == None => relation == None` 분기를 통과한다. SAMPLE schema가 마지막 `>= 1`을 충족하므로 Query closure 검증이 생략될 수 있다. 빈 Query binding 목록도 이 loop 자체에서는 거부되지 않는다.
- 최소 변경: fixture별 exact item/binding count와 producer kind를 먼저 요구한다. Query binding은 `schema().expect(...)`와 `relation().expect(...)`로 존재를 고정하고, schema key와 producer expression table의 closure를 검사한다. SAMPLE은 authored schema 존재와 relation 부재를 별도 기대값으로 고정한다. 현재 생산 projection은 Query의 둘 다 유지한다(`pipeline/src/execution.rs:1430-1436,1475-1476`).
- 종료 조건: Query binding 제거, Query schema/relation 동시 제거, 참조 key를 producer table에서 제거하는 mutation이 각각 실패한다. 전체 fixture 합산 counter로 대신하지 않는다.

## 선택 사항 / 문서 정합성

- **Surface diagnostic span:** `surface/tests/v3_family_hellgate.rs:187-199,454-458,749-755,1019-1025`에 code + message substring만 검사하는 rail이 남아 있다. P3 문서의 “남은 contains는 exact code+span 또는 witness가 있다”는 범위 주장은 현재 코드보다 넓다. 모든 메시지 golden을 추가할 필요는 없다. 사용자-facing 위치가 중요한 대표 case의 exact span을 고정하고 문서의 범위를 좁히면 된다.
- **Standalone Rust child timeout:** CLI `tests/support/mod.rs:11-16`, `tests/ingress_matrix.rs:48-53`, diagnostics `tests/binary_contract.rs:24,92`는 child wait 자체에 timeout이 없다. FIFO 전용 `run_os_bounded`만 10초 watchdog이 있다. `.config/nextest.toml:7`의 60초 test bound가 전체 gate를 보호하므로 이것을 CI 무한 hang 결함으로 분류하지 않는다. 직접 `cargo test` 운영 편의를 위해 공통 bounded helper를 도입할 수 있다. P8의 watchdog 설명도 해당 helper에 한정해 읽어야 한다.
- **Compiler mutation attribution:** `tools/qualification/tests/test_external_consumer_cache.py:475-487`의 compiler mutant는 nonzero exit만 요구한다. baseline positive control이 있어 전체가 무조건 실패하는 환경은 이미 구별한다. mutant별 expected compiler code/message를 추가하면 원인 귀속이 더 명확해진다. 생산 결함이나 현재 false-green으로 승격하지 않는다.
- **문서 범위:** 각 P 문서의 baseline/final counts와 source line은 당시 기록이다. 현재 inventory와 다르다는 이유만으로 과거 실행을 실패로 재분류하지 않는다. 이후 보고에는 source SHA, command, exit, targeted test, mutation diff/hash를 함께 남기면 재감사 비용을 줄일 수 있다.
- **Permutation 범위:** P5의 일부 rule-order rail은 120개 중 5개, diamond rule/body order는 48개 중 3개만 검사한다(`logic/tests/v3_rule_scc_hellgate.rs:383-435`, `v3_logic_recursion.rs:318-346`). 독립 343-graph oracle은 유지하고, 별도 determinism 완전성 목표가 있으면 이 작은 permutation 공간을 전수화한다. 현재 order-dependent 실패를 발견한 것은 아니다.
- **HIR source length:** P7의 base `source_len` 미검증 주장은 좁혀야 한다. extended accessor가 base를 직접 호출하며 `Some(12)` 테스트가 있다(`hir/src/span.rs:151-152,457`). unknown-id `None` control만 선택 사항으로 남는다.
